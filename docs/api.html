POST /api/v1/payout — Submit a batch of transfers

Creates a batch. Transfers are validated, written to SQLite as queued, and collected in the batch window before signing.

Required headers
HeaderDescription
X-Api-KeyAPI key (required on all endpoints except /health and /metrics)
X-Idempotency-KeyUnique string per operation. Same key + same body = same batch, no duplicate. Same key + different body = 409.
Content-Typeapplication/json
Request body
{
  "transfers": [
    {
      "to":       "EQAbcdef...",   // TON address (required)
      "amount":   "5.0",           // decimal TON or USDT (mutually exclusive with amountNano)
      "amountNano": 5000000000,    // nanoTON or USDT base units (mutually exclusive with amount)
      "comment":  "reward",        // optional text comment
      "currency": "TON"            // "TON" (default) or "USDT"
    }
  ]
}
Constraints
  • Maximum 254 transfers per request (Highload Wallet v2 limit). Exceeding returns 400.
  • USDT transfers require USDT_JETTON_WALLET to be set; otherwise 400.
  • Testnet addresses (kQ… / 0Q…) on mainnet return 400.
  • USDT amount accepts at most 6 decimal places.
Response 202 Accepted
{
  "batchId": "7f3a2c1e-4b56-4e89-a1f2-123456789abc",
  "status": "queued"
}
GET /api/v1/status/{batchId} — Batch status

Returns the current status of a batch, plus per-transfer details.

Response 200 OK
{
  "batchId":   "7f3a2c1e-...",
  "status":    "confirmed",
  "txHash":    "a1b2c3d4...",
  "createdAt": "2025-07-01T12:00:00Z",
  "sentAt":    "2025-07-01T12:00:03Z",
  "transfers": [
    { "to": "EQAbc...", "amount": "5.0", "currency": "TON", "status": "confirmed" },
    { "to": "EQDef...", "amount": "2.0", "currency": "TON", "status": "confirmed" }
  ]
}

Returns 404 if the batchId is unknown. If the batch was archived, it is retrieved from payout-archive.db transparently.

POST /api/v1/recovery — Trigger manual recovery sweep

Runs the same sweep as startup: checks all sending batches older than 5 minutes against the chain. Batches already in a block become confirmed; expired ones become failed.

No request body required. Returns 200 with a summary.

{ "swept": 2, "confirmed": 1, "failed": 1 }
GET /health — Liveness / readiness probe

No auth required. Returns 200 when SQLite responds and the wallet key file is present. Returns 503 otherwise (Docker / Kubernetes stops routing traffic).

{ "status": "UP" }

Batch Statuses

StatusMeaning
queuedSaved to DB, waiting for the batch window to close.
sendingSigning started. Bytes may already be in-flight.
pausedWallet balance too low. Retried after PAUSE_RETRY_MS. Alert sent to ALERT_URL.
sentTON Center accepted the bytes into the mempool.
confirmedMessage hash found in getTransactions. Final success.
failedMESSAGE_TTL_MS elapsed without confirmation. Retry with a new X-Idempotency-Key.

Webhooks

Set WEBHOOK_URL to receive batch events. The engine uses a persistent outbox: if delivery fails, it retries at 5 s, 30 s, 2 min, then every 10 min until 2xx.

Events: sent (fires immediately), confirmed, failed.

POST <WEBHOOK_URL>
Content-Type: application/json

{
  "batchId": "7f3a2c1e-...",
  "status":  "confirmed",
  "count":   2,
  "txHash":  "a1b2c3d4...",
  "error":   null
}

Your endpoint must respond 2xx. Any other response triggers a retry. The same event may be delivered more than once if the process restarts between receipt and the delivered mark — make your handler idempotent.

Error Codes

HTTPSituation
400Invalid address, testnet address on mainnet, missing USDT wallet, batch > 254, bad JSON.
401Missing or wrong X-Api-Key.
404Unknown batchId.
409Same X-Idempotency-Key, different request body.
429TON Center rate limit (retried internally, not surfaced to caller).
503Health check failed (SQLite unavailable or key file missing).
